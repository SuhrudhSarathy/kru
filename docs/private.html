Private buckets

Encrypt a bucket with a password. Locked, it doesn't exist as far as kru is concerned.

Using them

kru bucket add diary --private     # new, encrypted bucket (asks for a password)
kru bucket private home            # encrypt an existing bucket
kru task list --unlock             # show private buckets for this command

In the TUI, P unlocks and L locks again.

  • Locked private buckets are hidden from every command: lists, JSON output and task numbering. Their names are hidden too.
  • The password is typed on the terminal and can't be passed any other way, so scripts and agents can't read or change private buckets.
  • task add without -b fails if the active bucket is private and locked.
  • Notes of tasks in a private bucket are encrypted inside the bucket rather than kept as a plain file. They open only in your editor (task md --path is refused).
  • Making a bucket private moves its notes inside and deletes the plain files.

A forgotten password can't be recovered. Without it the tasks cannot be decrypted. There is no reset.

How it's encrypted

  • Key derivation: Argon2id (19 MiB, 2 passes by default) with a random 16-byte salt per bucket.
  • Cipher: XChaCha20-Poly1305, with a fresh random nonce every time the bucket is sealed.
  • What's encrypted: the bucket's name, tasks and notes, as JSON. The bucket id is used as associated data, so a sealed bucket can't be passed off as another.
  • What stays readable: only the header (id and timestamps), so sync can tell which version is newer without the password.

Private buckets sync like any other: the git remote only ever sees the encrypted form.
