Settings & storage

Where data lives

kru path prints the store directory. The first match wins:

  1. $KRU_DIR
  2. the dir setting
  3. your platform's cache folder

Inside are plain JSON files for buckets and tasks, plus notes/<id>.md for markdown notes. Files carry a format version: an older kru refuses to touch data written by a newer one, so upgrade rather than hand-editing. Several kru processes (say a CLI call and an open TUI) can share a store safely: saves lock the store and merge what another process saved meanwhile.

For a throwaway store (tests, dry runs): export KRU_DIR="$(mktemp -d)".

Settings

Stored in a JSON file in your config folder (kru config path; e.g. ~/.config/kru/config.json on Linux). $KRU_CONFIG points elsewhere.

KeyMeaningEffective value
dirWhere tasks are stored$KRU_DIR, else setting, else cache folder
editorCommand to open files, e.g. nvim, code --waitsetting, else $VISUAL, $EDITOR, then vi (notepad on Windows)
autosyncon/off: sync in the backgroundsetting, else off
kru config                       # everything, with where each value came from
kru config set editor "code --wait"
kru config set autosync on
kru config unset editor

Changing dir doesn't move existing data.
