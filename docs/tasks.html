Tasks & fields

What a task holds and how to set it.

Fields

FieldFlagValues
description-d, --descriptionOne line of text, required, up to 500 characters
ctx-c, --ctxExtra context; may span lines; up to 10,000 characters
priority-p, --prioritylow, medium, high (also l, m/med, h)
status-s, --statustodo, in-progress, done (also doing, wip)
due--dueSee below; none clears it

Kru also records created, edited and completed times, a stable id, and an optional notes file. Values are case-insensitive. Input is tidied: control characters are dropped and runs of spaces collapse.

Due dates

All parsed in your local time zone. A date without a time means the end of that day.

You typeMeaning
today, tomorrowEnd of that day
mon … sundayEnd of the next such weekday
2026-10-12End of that date
"2026-10-12 17:00"That exact time
3d, +2h, 1w, 2 daysNow plus that span
none, clear, -No due date

Ordering

Lists are ordered most urgent first: open before done, then earliest due date (no due date last), then higher priority.

Identifying a task

Commands take a <task> argument. It can be:

  • its number (digits only), as shown in task list. Numbers run bucket by bucket and can shift.
  • its id (UUID), or a unique start of it. Ids never change, even across devices.

Context vs. markdown notes

Context is a short text field on the task. Append with kru task ctx 1 -a "text"; replacing it asks for confirmation (or needs --force).

Markdown notes are for anything longer: kru task md 1 creates notes/<id>.md in your store (starting with the description as a heading) and opens it in your editor. --path prints the path instead, --remove deletes the file. Removing or pruning the task removes its notes too. Notes sync as text.

Done tasks and pruning

Tasks done more than 7 days ago are deleted whenever kru starts. Run it yourself with kru prune --days N.
