Syncing

Keep tasks in step across devices using any git remote.

Set up

Create an empty private repository (for example on GitHub). On each device, with the same URL:

kru sync init git@github.com:you/my-tasks.git

This turns the store directory into a git repository with an origin remote, writes a .gitignore for device-local files (state.json, locks), and runs a first sync. Requires git on your PATH. kru never prompts for credentials with --json; a remote that needs a password fails instead of waiting.

Everyday use

kru sync            # commit local changes, fetch, merge, push
kru sync status     # remote, last sync, local changes, ahead/behind (no network)

In the TUI press S. Turn on autosync (kru config set autosync on) to sync in the background after every change and every five minutes in the TUI. Output goes to sync.log in the store.

How merging works

Git moves the data and keeps history; kru does the merging. Every task and bucket has a stable uuid, so when two devices both changed things, kru does a three-way merge per task and bucket against their common ancestor:

  • A change made on one device is taken.
  • If the same field changed on both, the later edit wins.
  • An edit made after a delete elsewhere keeps the task; a delete made after an edit removes it.
  • Buckets with the same name are merged.
  • Markdown notes merge as text. If both devices changed the same lines, the more recently committed file wins.

Each decision is reported, e.g. priority: kept high over low. Nothing is silently lost: git history keeps every version.

Task numbers differ between devices and can shift after a sync. Ids are the same everywhere.

Privacy

Private buckets are encrypted before they are committed, so even your remote host only sees ciphertext for them. Other buckets are stored as readable JSON, which is why the repository should be private.
