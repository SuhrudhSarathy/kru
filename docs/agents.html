Scripts & agents

kru's JSON output is its stable interface. The repo ships a SKILL.md that teaches LLM agents to use it.

Ground rules

  1. Always pass --json. Text output may change.
  2. Never run bare kru from a script: it opens the interactive TUI.
  3. Check the exit code. Non-zero means failure with a one-line message on stderr.
  4. Refer to tasks by id, not number.
  5. Use --all to see done tasks.
  6. Append context (task ctx -a) instead of overwriting; replacing needs --force.

Task JSON

{
  "num": 1, "bucket": "home", "description": "Pay rent",
  "ctx": "Landlord: Sam", "priority": "high", "status": "todo",
  "due": "2026-10-12T11:30:00Z", "completed": null,
  "created": "2026-10-10T12:49:45Z", "edited": "2026-10-10T12:49:45Z",
  "mdpath": "notes/01a125dc-….md", "id": "01a125dc-bcef-7784-8fc5-17784df85dec"
}

Times are RFC 3339 UTC, so they compare correctly as strings. New keys may appear in future versions; ignore ones you don't know.

Recipes

# add and remember the id
id=$(kru task add -d "Write report" -p high --due fri -b work --json | jq -r .id)

# change fields and see what changed
kru task mark "$id" -s in-progress --json | jq .changes

# overdue tasks
now=$(date -u +%Y-%m-%dT%H:%M:%SZ)
kru task list --json | jq --arg n "$now" '[.[] | select(.due != null and .due < $n)]'

# complete them all
kru task list --json | jq -r --arg n "$now" '.[] | select(.due != null and .due < $n) | .id' \
  | xargs -r kru task done --json

# open tasks per bucket
kru bucket list --json | jq 'map({(.name): .open}) | add'

Private buckets and agents

Agents cannot see or change private buckets: the password can only be typed at a terminal. If a task can't be found, it may be in one; ask the user to run the command with --unlock.

Using the skill with Claude Code

Copy SKILL.md into a .claude/skills/kru/ directory (project) or ~/.claude/skills/kru/ (personal) and the agent will use kru for task requests. The file also documents the complete error table.
